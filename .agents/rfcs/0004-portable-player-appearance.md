# RFC 0004：跨世界玩家头像美化

> 状态：Draft
> 日期：2026-09-06
> 关联：RFC 0002、RFC 0003

## 背景与目标

本地 goose 演示包强制依赖 games.loreloom.rainbound-inn，并用 replace_definition 替换
character/traveler 的整张角色定义来附加 appearance。因此其它世界缺少依赖时会拒绝加载；删除
依赖也无法解决固定 Patch 目标不存在的问题。替换还会携带原世界的属性、资源与角色资料。

目标是同一个本地头像美化 Mod 在不同世界、fixed/preset/ugc 玩家及已有存档中启用即可显示，禁用
即可恢复原头像。资源仍留在被 ignore 的本地 Mod 内，不随开源仓库提交。

## 候选决策

在 Mod Manifest 初始 v1 增加可选的玩家头像展示覆盖声明，引用稳定 appearance model ID 及可选
参数值。具体字段命名在接受时冻结。这是纯展示覆盖，不是新 Character Definition 或世界 Patch。

- Content 负责校验 appearance capability、模型来源、参数类型、依赖和哈希；声明纳入 ModLock。
- Runtime 负责识别实际玩家，在生成 UiSnapshot 的玩家头像投影时采用声明的模型和参数；省略参数
  使用该模型自己的默认值，不从不相关模型猜测参数映射。
- ECS 中的 CharacterAppearance 仍是角色语义外观的权威状态；展示覆盖不修改它，不修改角色属性、
  身份、Agent Context 或存档记录。其它头像与 NPC 不受影响。
- Appearance/TUI 继续负责已有图层合成、动画和终端协议；不按 goose 包名特判，不读取世界私有 ID。
- 没有覆盖时维持原头像投影。多个启用 Mod 声明玩家头像覆盖时编译失败，要求只启用一个；不依赖
  文件扫描顺序或隐式优先级。

## 存档与失败边界

新建和载入存档采用同一展示投影规则。禁用美化包恢复保存的角色外观；原角色本来没有外观时恢复
现有无图回退。由于本方案不把覆盖模型 ID 写入角色记录，禁用覆盖包本身不会制造角色外观缺失引用。
其它内容引用仍走既有存档重建校验。

无效模型、参数或多个覆盖应在 Launcher 候选编译阶段失败，保留旧 loadout。禁止为了兼容跨世界而
跳过依赖、Patch 目标、命名空间或资源完整性检查。

## 取舍与非目标

本方案提供玩家头像美化；不提供所有角色外观自动适配、跨模型衣服/发型语义映射、通用角色选择器、
运行中 Mod 热启停或剧情机制修改。需要改变角色语义外观的 Mod 仍走既有显式内容路径。

另一方案是在玩家创建或读档时重写 CharacterAppearance，但这会引入持久变更、禁用恢复和旧值
provenance，本次不建议采用。

## 验收

1. 用自建测试图片和无世界依赖的同一 Mod 在两个不同 namespace 的世界验证启停。
2. fixed、preset、ugc 玩家和已有存档投影一致，原角色记录及属性不变。
3. 禁用覆盖恢复原头像或无图回退；动画沿用现有实现。
4. 缺失模型、参数错误、覆盖冲突均在保存 loadout 前失败。
5. 改写本地 goose 包以去掉 rainbound-inn 依赖和角色替换 Patch，重算内容哈希；社区图片不提交。

## 待确认

是否采用“当前玩家的纯展示覆盖”作为通用头像美化契约？确认后同步 Active Spec、建立实施清单，
再实现并更新本地 goose 包。当前 Draft 不构成实现授权。
