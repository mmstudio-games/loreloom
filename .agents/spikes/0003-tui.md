# P0 Spike 0003：Ratatui/Crossterm TUI

> 状态：Completed
> 开始日期：2026-08-30
> 完成日期：2026-08-30
> 规范来源：[Runtime Active Spec §12](../specs/runtime.md#12-tui-规范)

## 目标

验证 Loreloom 可以用确定性的拥有所有权 View Model 实现 Codex 风格终端界面，并在不访问 ECS、
Store 或真实 Provider 的条件下覆盖宽屏/窄屏布局、Unicode 多行输入、流式更新、resize 与终端恢复。

## 固定候选输入

- `ratatui = 0.30.2`，关闭 default features，仅启用 `crossterm`；
- `crossterm = 0.29.0`；
- `unicode-segmentation = 1.13.3`，只用于 Spike 的 grapheme-safe 编辑器；
- 全部来自 crates.io registry，不使用 Git branch、本地路径或真实 TTY 集成测试。

## 候选交互

- `width >= 80` 使用左侧约 30% 状态 + 右侧叙事/输入的双栏；
- `width < 80` 使用 State/Story 可切换单页，输入区始终位于底部；
- `Enter` 提交，`Alt+Enter` 或 `Ctrl+J` 插入换行；
- 运行中 `Esc` 请求取消，空闲时不把它解释为 WorldCommand；
- resize 只改变投影布局，不修改输入、grapheme cursor、历史或 transcript scroll；
- streaming 文本是 ephemeral row，finalize 后由新 View Model 决定是否成为 committed transcript。

候选按键与阈值只有在本 Spike 通过并同步回 Active Spec 后才冻结。

## 验收

- [x] Ratatui `TestBackend` 宽屏快照包含左侧状态、右侧 transcript 与固定底部输入；
- [x] 窄屏快照可以切换 State/Story，两个页面都保持输入区可达；
- [x] resize 往返不改变编辑内容、Unicode cursor、history、scroll 或 streaming 数据；
- [x] 多行编辑按 grapheme cluster 插入、移动与删除，不切断组合字符或 emoji；
- [x] submit/cancel/quit 只产生 UI intent，不直接生成 WorldCommand；
- [x] streaming chunk 更新 ephemeral row，finalize/interrupt 状态可区分；
- [x] Tool pending/succeeded/rejected/failed 有确定性的不同视觉状态；
- [x] terminal session 在正常 drop、初始化失败回滚和 panic unwind 时对称恢复 raw mode、alternate
  screen、cursor 与 paste/mouse 状态；
- [x] 测试不要求真实 TTY、网络、ECS 或 Provider；
- [x] 记录依赖、快照、已知终端兼容缺口与最终结论。

## 禁止提前冻结

Spike 可以定义测试专用 View Model、InputEditor、UiIntent、renderer 和 TerminalOps，但不得把这些
类型直接升级为 `loreloom-core`/`loreloom-tui` 公共 API。最终 View Model 和事件协议仍需独立冻结。

## 自动化证据

测试文件：`crates/loreloom-tui/tests/tui_spike.rs`。

- 80-column 宽屏快照固定左侧 30% State、右侧 Story 和全宽底部 Input；48-column 快照分别固定
  State/Story 页面，并验证两个页面均保留 Input；
- `InputEditor` 用 extended grapheme cluster 定位 cursor，组合字符、ZWJ family emoji、CJK、换行与
  emoji 的插入和删除均不产生半个 grapheme；
- Crossterm key mapping 验证 `Enter`、`Alt+Enter`、`Ctrl+J`、运行中/空闲 `Esc` 与 `Ctrl+C`；
  返回值仅为 Submit/Cancel/Quit UI intent；
- streaming row 在 Live/Final/Interrupted 间显式转换，不自动进入 committed transcript；
- Tool 的四种状态同时具有文本标签和不同颜色，不能只依赖颜色传达语义；
- mock `TerminalOps` 验证正常 drop、在 bracketed paste 初始化失败以及 panic unwind 三条路径；所有
  已启用终端状态均按 mouse、paste、cursor、alternate screen、raw mode 的逆序恢复；
- 100 -> 50 -> 100 columns 的渲染往返不改变 editor、grapheme cursor、history cursor、transcript
  scroll 或 streaming 数据。

验证命令：

```sh
cargo test -p loreloom-tui --test tui_spike
cargo clippy -p loreloom-tui --all-targets -- -D warnings
```

结果：7 passed，Clippy 无警告。

## 兼容边界与后续实现要求

- TestBackend 证明 View Model 与 renderer 的确定性，不替代 macOS/Linux/Windows 真实 TTY smoke test；
  产品装配阶段仍需验证 Crossterm event polling、signal/panic hook 集成和重复恢复的幂等性；
- bracketed paste 与 mouse capture 的生命周期已冻结，但 paste event 内容限制、IME 行为和 mouse
  交互不是本 Spike 的公共协议；
- 颜色只作为增强。产品 UI 必须保留 pending/succeeded/rejected/failed 文本或等价符号，并遵守终端
  能力降级；
- 本 Spike 不冻结 `UiSnapshot`、`UiIntent`、`InputEditor` 或 terminal session 的 Rust 类型布局；它只
  冻结 Runtime/TUI 边界可观察到的语义。

## 最终结论

Spike 通过。Ratatui/Crossterm 可以承载第一阶段 Loreloom TUI；80-column 响应式门槛、默认 30% 状态
栏、grapheme-safe 多行输入、UI-only intent、ephemeral streaming 与终端逆序恢复已经同步回 Active
Spec。生产 API 仍需在纵向切片阶段按这些语义建立，测试专用类型不升级为公共 API。
