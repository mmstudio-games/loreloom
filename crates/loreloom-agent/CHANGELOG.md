# Changelog

## v0.1.0-alpha.0

### Bug Fixes

- [`443f748`](https://github.com/mmstudio-games/loreloom/commit/443f748a9c7d761c76d0fbbf6563c551f2cf3927): Preserve sanitized model-call failure categories, invocation stages, safe Provider metadata, and a shared `err_` correlation ID from Armillae through AgentRunner and Runtime. Show the same diagnostic in TUI/headless failures, return NPC failures to the Narrator without exposing raw Provider text, and ignore local Provider configurations and save data.
- [`cdd11e8`](https://github.com/mmstudio-games/loreloom/commit/cdd11e89b4db2c81c9a190560362d710f30961c9): Remove the Manifest and Runtime response-language policy and its English system messages. Let root world and Mod Narrator/NPC prompts own fixed or player-following language behavior without a separate compatibility field.

### Chores

- [`fbaf03e`](https://github.com/mmstudio-games/loreloom/commit/fbaf03eeeaecb8d2ed8192a6c3d0bfce7805cd80): Validate explicit Armillae model/tool continuation and Narrator-to-NPC orchestration with ordered correlation, current-revision reprojection, committed fact provenance, configurable two-level budgets, cancellation, and stale-result handling.
- [`b930503`](https://github.com/mmstudio-games/loreloom/commit/b93050356875b9ec413f48bda885ff276c218ab9): Freeze safe real-time Tool Activity as an ephemeral Runtime-to-TUI progress protocol. Tool calls become pending immediately before execution and settle after their result, while raw arguments, ToolResult data, Provider text streams, Transcript state, and persistence remain outside the activity channel.
- [`2b4a40e`](https://github.com/mmstudio-games/loreloom/commit/2b4a40e196895715103289ee4f6e3c9391c5c568): Initialize the Loreloom Cargo workspace, crate boundaries, version policy, Semifold configuration, and implementation gates.

### New Features

- [`91ca3ac`](https://github.com/mmstudio-games/loreloom/commit/91ca3ac93fbeda411d7ca56e7735e3ada0634121): Expose bounded stable-ID inventory and skill queries plus transfer, equip, split-stack, and active-skill command tools for the current actor. Preserve all committed event IDs across Agent tool continuation and cover ownership, pagination, revision advancement, durable effects, and UI snapshot projection with Mock Bridge tests.
- [`48ae109`](https://github.com/mmstudio-games/loreloom/commit/48ae109376f72ef8c7de4927f95b4ba9e4a187a5): Add strict Agent protocols and budgets, ordered Armillae tool continuation with wakeable cancellation, trusted transcript commands, content-resolved immutable view models, and a durable Narrator-to-NPC Runtime over the SurrealKV world service.
- [`ab0e0c5`](https://github.com/mmstudio-games/loreloom/commit/ab0e0c57e206fb7eeb40d1fe2ba99cbd26926dae): Apply configurable bounded projections to narrator and NPC contexts for transcript bytes and entries, visible actors, inventory, skills, knowledge, and goals. Mark truncated observations, reject oversized requests before provider I/O with a deterministic token estimate, filter forgotten facts, and validate host limits from strict product configuration.
- [`62ba87c`](https://github.com/mmstudio-games/loreloom/commit/62ba87cb62fc453c18c39a426e6bfabffe17883f): Execute typed event options, capability-gated gameplay actions, save/session parameters, and deterministic declarative rule cascades through durable runtime tools.
- [`1924090`](https://github.com/mmstudio-games/loreloom/commit/1924090337b8714351738ccc9b67c7f3a6074780): Let root worlds and enabled Mods declare ordered Narrator and NPC global context through the same `[prompts]` manifest table. Append Mod prompts deterministically by dependency topology without granting Tools or capabilities, include their source files in content locks, and keep undeclared prompt resources out of Agent requests.
- [`861dac2`](https://github.com/mmstudio-games/loreloom/commit/861dac2993e536412697d3a6723e18e623b4d02b): Raise the default per-Agent and per-player-input Model, Tool, token, byte, turn, round, and elapsed budgets so repeated tool continuations and multi-agent narration can complete without requiring immediate configuration tuning.
- [`7670551`](https://github.com/mmstudio-games/loreloom/commit/7670551dc382614afee328e3455ea261af4d44bf): Define a higher default budget profile for repeated tool continuations within one Agent turn and multi-round Narrator/NPC orchestration within one player input, while keeping every limit configurable and cancellation responsive.
- [`e3c470d`](https://github.com/mmstudio-games/loreloom/commit/e3c470d609c848c3083f4045ad31b1d288e157d7): Start NPC materialization immediately after an accepted `create_npc` call. Successful orchestration tools now end their model turn through a ToolResult barrier, skipping unused prose and later calls from the same response before the runtime replans against the committed character.
- [`33b3fb8`](https://github.com/mmstudio-games/loreloom/commit/33b3fb831b7a1c2a0e51a713dd82c8e88cd6bdbd): Define an accepted `create_npc` call as a narrator turn barrier so character materialization starts immediately without an unused model continuation, while preserving post-commit replanning.
- [`6640d49`](https://github.com/mmstudio-games/loreloom/commit/6640d4960358e891b8debd8f12ee108e03246dcf): Use Provider-native tool calls to build narrator orchestration plans, request ordered NPC turns, and submit generated NPC drafts. Treat all narrator, NPC, and generation response bodies as natural language, associate NPC claims with committed world events at runtime, and preserve JSON-looking prose as literal narration.
- [`234db6d`](https://github.com/mmstudio-games/loreloom/commit/234db6d8318366ec014b51c48e3f7869f787e5db): Make generated NPC drafts minimal and recoverable: trusted agent profiles now come only from the locked generation policy, empty role collections may be omitted, knowledge and goal schemas match their Rust wire types, and invalid drafts report safe field categories. End the generation stage on the first accepted draft instead of spending another model call on discarded prose.
- [`8ba5678`](https://github.com/mmstudio-games/loreloom/commit/8ba567805973c726ea692ba8521772f94c1f02d8): Define NPC generation as a single-purpose tool stage that ends on the first accepted draft, keeps trusted agent bindings out of model input, accepts omitted empty collections, and reports only safe field-level draft validation categories.
- [`bf09e71`](https://github.com/mmstudio-games/loreloom/commit/bf09e71e0f40433a92be8900373f6f6ffd2541e7): Materialize preset and generated NPCs through the shared character factory after the narrator planning turn, then replan with the committed actor and full scene projection before dispatching a dynamically registered NPC agent. Add strict NPC decision wires, generation policies and resource limits, orchestration idempotence, unoffered-tool rejection, and durable Mock Bridge coverage for budgets, cancellation, provider failure, and save rebuilds.
- [`7197245`](https://github.com/mmstudio-games/loreloom/commit/719724597653f1805c6de82e935e9a3dfd068acc): Publish safe Tool Activity as each accepted ToolCall starts and settles instead of waiting for the player turn to finish. Propagate the current activity list through Runtime and the non-blocking UI adapter, render live pending and terminal states without raw arguments or results, and keep the final display ordered between player input and Narrator prose.
- [`ccf768f`](https://github.com/mmstudio-games/loreloom/commit/ccf768f4a7e21bb445a669f9e6d39c660dbf5842): Load the single playable world from root-level manifest, content, and prompt files; persist its exact WorldLock separately from enabled extension Mods; inject world-owned narration and language policy into Narrator and NPC turns; and remove production demo content and mock bridges. Keep all pre-release save and domain payload structures on their initial v1, rejecting obsolete development saves instead of adding compatibility migrations.
- [`c71e7d4`](https://github.com/mmstudio-games/loreloom/commit/c71e7d451c4c996637b2291a6a9b40beea7ad94a): Simplify narrator NPC orchestration to `create_npc` and `request_npc_turn`, while keeping materialization, generation, replanning, and NPC execution inside the runtime. Move the default generation policy into locked world content, derive scene and agent bindings from authoritative state, advertise only currently schedulable actor IDs, and surface sanitized tool rejection codes in the TUI.
- [`336418d`](https://github.com/mmstudio-games/loreloom/commit/336418de267bf45c3d4ebcca77418b93560be492): Add the production terminal UI, non-blocking Runtime client adapter, stable cross-turn cancellation, and a persistent headless demo executable.

### Dependencies

- Update loreloom-core to 0.1.0-alpha.0.
